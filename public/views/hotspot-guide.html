📶 Teacher & Student Hotspot Deployment Guide

Follow these steps to host an un-proxyable attendance session in any classroom, lecture hall, or lab.

Step 1: Host Creates the Wi-Fi Hotspot

The teacher or host computer serves as the Wi-Fi hotspot and server.

On Windows 10 & 11:
  1. Press Win + I to open Settings.
  2. Go to Network & Internet ➔ Mobile Hotspot.
  3. Toggle Mobile Hotspot to ON.
  4. Set your Network Name (e.g. Classroom-Attendance) and a simple password.
  5. Note: Windows automatically assigns the host IP 192.168.137.1 to this hotspot.
On Android / iPhone Hotspot or College Wi-Fi:

You can also connect both teacher laptop and student phones to the same College Wi-Fi router or phone hotspot. The server will automatically detect the interface IP!

Step 2: Start the Node.js Server

In your terminal inside the project directory, run:

npm start

Open http://localhost:3000 in your laptop browser, click Start New Session, and project the screen to the classroom projector!

Step 3: Students Connect & Scan

Students in the classroom connect their phones to the Hotspot and point their camera at the projected dynamic QR code.

  • The QR code link directly opens: http://<HOST_IP>:3000/student
  • The server checks the student's physical IP in the local ARP table to extract their hardware MAC address.
  • First time students enter their Roll Number to lock and register their phone.
  • On all future lectures, attendance is marked in 1 click with zero typing!

💡 Note on Android & iPhone "Private / Randomized MAC"

Modern smartphones use "Randomized MAC Address" for privacy. Good news: Android and iOS assign a consistent, permanent randomized MAC per Wi-Fi network SSID. This means as long as students connect to the same hotspot SSID (e.g. Classroom-Attendance), their MAC remains 100% constant across every lecture!

If a student switches or re-randomizes, they can toggle "Use Device MAC" in their phone's Wi-Fi Settings ➔ Hotspot Name ➔ Advanced/Privacy. The teacher can also click "Reset MAC" on the Students Directory anytime.

🛡️ How Proxy Attendance is 100% Prevented

  • Cannot mark from outside: The server runs on a private local IP (e.g. 192.168.137.1). Students outside the classroom cannot reach this address.
  • Cannot proxy for friends: A single physical phone (MAC) can only submit attendance ONCE per session. If Student A attempts to mark for Student B from the same phone, the system rejects it immediately with an audible alert on the teacher's screen!
  • Cannot forge phone identity: Student Roll Numbers are bound to their device MAC address in the database. Using someone else's phone triggers an instant "MAC Mismatch" security block.
  • Cannot share QR photos: The QR code rotates dynamically every 20 seconds. An expired token will be immediately rejected.
